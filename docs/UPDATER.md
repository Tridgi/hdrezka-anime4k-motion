# Обновления HDREZKA Anime4K Motion

## Каналы
- **Стабильный** — последний опубликованный GitHub Release без отметки prerelease, распространяется из main.
- **Тестовый** — последний prerelease с тегом `test-<sha10>`, собираемый только из `fix/player-swapchain-dpi-scaling` по workflow `testing-release.yml` после успешного `dotnet test`.
- GitHub Actions artifacts не используются для клиентских обновлений: у них ограниченный срок хранения, а API загрузки требует авторизации.

## Обновление
1. В настройках выбирают канал и нажимают «Проверить обновления».
2. Сервис запрашивает список GitHub Releases именно `Tridgi/hdrezka-anime4k-motion`, находит архив `HDREZKA-*-win-x64.zip` и SHA-256 (поле digest или `SHA256SUMS.txt`).
3. Кнопка «Скачать и установить» открывает подтверждение. Архив скачивается с прогрессом и отменой, размер ограничен 700 МиБ. Без правильной контрольной суммы установка запрещена.
4. Доверенный `Updater/InstallUpdate.ps1` копируется в отдельную временную папку и запускается независимым процессом. Приложение закрывается.
5. Помощник дожидается завершения процесса, проверяет SHA-256 повторно, отклоняет ZIP с выходом за каталог, символьными ссылками или сверхнормативным объёмом, распаковывает рядом с текущей версией, сохраняет старую папку как `.backup-...` и устанавливает новую. При исключении пытается восстановить старую папку; журнал — в `%APPDATA%/HDREZKA-Anime4K-Motion/updater.log`.
6. Настройки и история находятся в AppData и при замене каталога не затрагиваются.

## Ограничения
- Старый стабильный выпуск v2.0.0 создан **до** нового обновлятора и не позволяет переключаться обратно на тестовый канал из приложения. Поэтому автоматическая установка именно этой стабильной версии заблокирована, пока не опубликована новая стабильная версия после тестирования/слияния в main.
- Обновление из каталога под Program Files может потребовать прав администратора; приложение не запрашивает повышение прав автоматически. При отказе старый каталог остаётся или восстанавливается.
- Скрипт и его rollback компилируются/проверяются в CI, но фактическую замену файлов необходимо проверить на Windows вручную.
- Программой устанавливаются только готовые релизы. Произвольные ветки из интерфейса не выполняются.


## Проверка исправления `Application did not exit` (2026-11-01)

Причина: метод `ChannelUpdateService.DownloadAndRestartAsync` вызывал `Application.Current.Exit()`
после `ConfigureAwait(false)` в продолжении фонового потока. WinUI 3 требовал вызова
из UI-потока, поэтому отдельный PowerShell-помощник ждал 120 секунд и выдавал
`Application did not exit`, не заменяя файлов.

Исправление `4b2e21ff52` переносит завершение в `SettingsPage.InstallUpdateButton_Click`
на UI-поток. До выхода сохраняются настройки, через 8 секунд предусмотрен аварийный
выход, если приложение осталось висеть после штатного `Application.Exit()`.
Добавлен `scripts/test-updater.ps1`, запускаемый в обеих Windows CI-задачах:
сценарий проверяет распаковку, замену файлов, backup и запись версии.

**Проверка на реальном Windows (обязательна):**
1. Скачать и вручную распаковать `test-4b2e21ff52` в новую папку, закрыв предыдущую копию.
2. Дождаться следующего тестового релиза, выбрать «Тестовый (пререлизы)» и нажать
   «Проверить обновления», затем «Скачать и установить».
3. Убедиться, что приложение закрывается без `Application did not exit`,
   запускается обновлённая версия, текущий идентификатор коммита изменился.
4. Проверить `%APPDATA%\HDREZKA-Anime4K-Motion\updater.log` на сообщение `Installed`
   и появление соседней папки `.backup-...` с предыдущей версией.
5. Убедиться, что история просмотра, язык, параметры плеера и вход в аккаунт не потерялись.

CI-smoke использует тестовый исполняемый файл вместо WinUI, поэтому **не**
подтверждает фактическое завершение WinUI-процесса: эту часть проверяют на ноутбуке.
