# Обновление HDREZKA Anime4K Motion 2.1

[← README](../README.md) · [Релиз 2.1.0](https://github.com/Tridgi/hdrezka-anime4k-motion/releases/tag/v2.1.0) · [Публикация](RELEASES.md)

## Каналы и проверка версий

- **Стабильный** — опубликованные GitHub Releases без `prerelease`, с тегом `vX.Y.Z`; текущий целевой релиз — `v2.1.0`.
- **Тестовый** — выпуски с `prerelease` и тегом `test-<commit>`, собранные из разрешённых тестовых веток (включая `fix/ratings-updates-polish`).
- **Тег + commit** отображаются в диагностике установленной версии. Приложение не считает выпуск новым, если тег или подтверждённый commit совпадают с установленными.

Обновление проверяется в **Настройки → Обновления**. Выберите канал, нажмите «Проверить обновления»; история версий открывается там же. Результаты API кэшируются, поэтому новый выпуск может появиться не сразу после публикации.

## Проверка GitHub Releases

`ReleaseCatalog.ApiUrl` использует `https://api.github.com/repos/Tridgi/hdrezka-anime4k-motion/releases?per_page=100`.

Из ответа отбираются только релизы нужного канала с доверенными HTTPS-адресами GitHub, содержащие ZIP `HDREZKA-*-win-x64.zip`. SHA-256 получают из поля `digest` либо файла `SHA256SUMS.txt`. **Без подтверждённого хэша установка запрещается.**

`ChannelUpdateService` кэширует список релизов на диске и в памяти (обычный TTL 20 минут); ручные запросы ограничиваются интервалом 2 минуты. При лимитах GitHub 403/429 или сбоях сети может показываться кэш с предупреждением об устаревании, однако это не подтверждение свежей проверки.

## Пошаговая автоматическая установка

1. Пользователь подтверждает загрузку нового ZIP. Ограничение размера — **700 МиБ**.
2. Архив скачивается с прогрессом и проверяется по SHA-256 до запуска helper.
3. Доверенный локальный `Updater/InstallUpdate.ps1` копируется в отдельный временный каталог и запускается независимо от основного приложения.
4. WinUI-приложение завершает работу через UI-поток, чтобы helper мог дождаться освобождения файлов.
5. Helper повторно проверяет архив, отвергает попытки выхода за каталог, ссылки и слишком большой объём распакованных файлов.
6. Существующая папка программы переименовывается в резервную копию `.backup-...`; новая версия разворачивается рядом и запускается.
7. При ошибке выполняется попытка восстановить предыдущую папку. Подробный журнал сохраняется в `%APPDATA%\HDREZKA-Anime4K-Motion\updater.log`.

**Не затрагивается** папка пользовательских данных `%APPDATA%\HDREZKA-Anime4K-Motion` с настройками, историей и состоянием аккаунта. Если программа установлена в `Program Files`, может потребоваться запуск с правами на запись; helper не обходит системные разрешения.

## Обновление вручную

Если встроенный механизм не находит выпуск или не может установить его:

1. Скачайте ZIP из [стабильного релиза v2.1.0](https://github.com/Tridgi/hdrezka-anime4k-motion/releases/tag/v2.1.0).
2. При необходимости проверьте SHA-256 с `SHA256SUMS.txt`.
3. Полностью закройте приложение и распакуйте ZIP в **новую отдельную папку**; не смешивайте части файлов разных версий.
4. Запустите новую `HDREZKA.App.exe` и убедитесь, что версия в настройках соответствует установленной.
5. Оставьте резервную копию старого каталога, пока новая версия не проверена. **Не удаляйте AppData.**

Старая стабильная 2.0.0 была выпущена до нового канального обновлятора. Если в ней нельзя выбрать нужный канал, используйте ручную установку 2.1.0 в отдельную папку.

## Сценарии тестирования

Автоматические проверки выполняются в `scripts/test-updater.ps1` на Windows runner и проверяют:
- распаковку и обновление тестового каталога;
- резервную копию и восстановление при сбое;
- синтаксис PowerShell-helper и проверку контрольной суммы.

**Чего они не подтверждают:** фактическое закрытие настоящего окна WinUI, наличие прав на запись в произвольную системную папку, поведения антивируса/драйверов и сетевые ограничения пользователя. Для этого необходим ручной тест на реальной Windows.

### Диагностика

| Симптом | Действие |
| --- | --- |
| «Обновления нет», хотя релиз уже опубликован | Убедитесь, что выбран стабильный канал; проверьте страницу GitHub и кэш (20 минут, throttle 2 минуты) |
| Ошибка SHA-256 | Не устанавливайте ZIP, скачайте заново с официального GitHub Release |
| «Application did not exit» | Проверьте `updater.log`, завершите зависший процесс, затем используйте ручную установку в отдельный каталог |
| Нет прав доступа | Устанавливайте в каталог с правом записи, не изменяя AppData |
| Приложение не запускается после замены | Проверьте backup, целостность распаковки, наличие `runtime`/`motion`/`shaders` |

Не отправляйте в публичные Issues файлы с cookies, логинами, токенами или другими приватными данными.

## Изменения механизма в ветке 2.1

В ранних тестовых сборках `Application.Current.Exit()` вызывался из фонового продолжения `ConfigureAwait(false)`, из-за чего helper мог ждать до тайм-аута. Завершение перенесено в UI-обработчик, с дополнительным резервным выходом. Добавлены проверки ZIP, SHA-256, резервирования и восстановления, а также разделение stable/testing и история версий.
