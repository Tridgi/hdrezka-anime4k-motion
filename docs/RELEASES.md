# Публикация релизов и история версий

История версий в приложении отображает до 20 последних GitHub Releases каждого канала. Выбор канала — в окне «История версий» раздела «Настройки → Обновления».

- Тестовый канал: ветка `fix/player-swapchain-dpi-scaling` → GitHub Actions `testing-release.yml` → prerelease `test-<sha10>`. В описании используется накопленный раздел `## [Unreleased]` файла `CHANGELOG.md`.
- Стабильный канал: после тестирования PR слить в `main`. Заменить накопленный `## [Unreleased]` на заголовок `## vX.Y.Z` и написать понятные пользователю изменения; создать новый пустой `## [Unreleased]` для следующего цикла, зафиксировать это в `main`.
- Затем на `main` создать и отправить тег `vX.Y.Z`. GitHub Actions `stable-release.yml` проверяет, что тег указывает на коммит в `main`, собирает Windows x64, тестирует установщик и публикует архив, SHA256SUMS и **описание из соответствующего раздела CHANGELOG.md**.
- Пока новый стабильный релиз не опубликован, `v2.0.0` остаётся последним стабильным; тестовая версия не превращается в стабильную автоматически при слиянии PR.
- Текст истории берётся через GitHub Releases API, а не зашивается в бинарник. Описание нужно поддерживать в `CHANGELOG.md` до создания тега.

**Ограничения:** список API ограничен последними 100 релизами проекта; при очень большом количестве тестовых сборок понадобится пагинация. Для проверки и скачивания нужен доступ к GitHub.
