# Выпуск HDREZKA Anime4K Motion

[← README](../README.md) · [Стабильная 2.1.0](https://github.com/Tridgi/hdrezka-anime4k-motion/releases/tag/v2.1.0) · [История изменений](../CHANGELOG.md)

## Модель выпусков

| Канал | Исходник | GitHub Release | Для кого |
| --- | --- | --- | --- |
| **Стабильный** | Зафиксированный коммит в `main` | `vX.Y.Z` без prerelease | Пользователи, которым нужна проверенная сборка |
| **Тестовый** | `fix/ratings-updates-polish` или `fix/player-swapchain-dpi-scaling` | `test-<10 символов SHA>` с prerelease | Тестирование новых изменений |

Для обновлений используются выпуски **этого** репозитория. Встроенная история показывает релизы выбранного канала из GitHub Releases API; GitHub Actions artifacts не используются как источник обновлений, поскольку имеют ограниченный срок хранения и требуют дополнительного доступа.

## Чек-лист стабильного выпуска

1. Внести изменения в тестовую ветку и проверить необходимые сценарии.
2. Обновить `Directory.Build.props`: `Version`, `FileVersion`, `AssemblyVersion`, `InformationalVersion`, `Product`.
3. Обновить README (RU/EN), `CHANGELOG.md`, руководство и сведения о выпуске, а также имена ZIP-архивов в CI.
4. Прогнать unit-тесты, проверки XAML, низких разрешений SVPflow, portable-публикацию, проверку ZIP, установщика и возврата резервной копии.
5. Провести ручную проверку интерфейса на Windows при нескольких размерах окна/DPI, проверить выбор зеркала и, при необходимости, реальные комментарии.
6. Слить проверенную ветку в `main` и закрепить стабильный тег. Никогда не присваивать стабильный тег непроверенной ветке.
7. Убедиться, что GitHub Release содержит архив, файл `SHA256SUMS.txt`, содержательные release notes из `CHANGELOG.md`, **не** помечен как prerelease и доступен через стабильный канал.

## Специальная публикация версии 2.1.0

В `.github/workflows/stable-release.yml` предусмотрен единовременный запуск **после слияния в main с названием merge-коммита, начинающимся с `release: v2.1.0`**. Сборка сначала проверяет, что commit принадлежит `main`, что версия совпадает с `Directory.Build.props`, и выполняет все автоматические тесты.

После успешной сборки/упаковки этот workflow:

1. создаёт `refs/tags/v2.1.0` на проверенном коммите `main`, если тег ещё не существует;
2. отказывается перемещать тег, если он уже указывает на другой коммит;
3. загружает в **стабильный** GitHub Release `HDREZKA-Anime4K-Motion-2.1.0-win-x64.zip` и `SHA256SUMS.txt`;
4. формирует описание из заголовка `## v2.1.0` файла `CHANGELOG.md`;
5. помечает выпуск как Latest.

На обычных будущих коммитах `main` дополнительный релиз не создаётся: для следующих версий используется стандартная публикация тега `vX.Y.Z`. Тег в `main` также запускает стабильный workflow при обычном push.

**Идемпотентность:** повторный запуск с тем же тегом проверяет SHA тега и при необходимости перезаливает архив/контрольную сумму. Не переиспользуйте один стабильный номер версии для отличающегося исходного кода.

## Манифест и обновлятор

`ReleaseCatalog` принимает ZIP с именем, начинающимся на `HDREZKA-` и оканчивающимся на `-win-x64.zip`. Название `HDREZKA-Anime4K-Motion-2.1.0-win-x64.zip` этому условию соответствует.

При выпуске создаётся `SHA256SUMS.txt` с хэшем **именно опубликованного** архива. Приложение сверяет хэш с GitHub digest или этим файлом; без совпадения установка невозможна.

Версия исполняемого файла читается из `Directory.Build.props`, а сборочный commit — из `SourceRevisionId`. Тег и SHA присутствуют в метаданных обновления и истории версий.

## Проверка стабильного выпуска

После публикации откройте:

- [GitHub Releases](https://github.com/Tridgi/hdrezka-anime4k-motion/releases);
- [GitHub Actions](https://github.com/Tridgi/hdrezka-anime4k-motion/actions);
- настройки приложения, стабильный канал и историю версий.

Проверьте, что `v2.1.0` доступен не как prerelease, ZIP скачивается, версия внутри приложения отображается как 2.1.0, а предыдущие настройки сохраняются.

## Ограничения

- GitHub API выдаёт ограниченное количество последних релизов; кэш и частые тестовые сборки могут задерживать появление нового стабильного выпуска в приложении.
- CI подтверждает сборку/тесты и сценарий установки на синтетических файлах, но не может гарантировать поведение всех зеркал, CAPTCHA или WinUI на каждом ПК.
- Для выпуска через GitHub Actions необходимы разрешения `contents: write` и работоспособный workflow на Windows runner.
